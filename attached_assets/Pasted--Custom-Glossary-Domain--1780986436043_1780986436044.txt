၁။ Custom Glossary (ဝေါဟာရ အဘိဓာန်) ထည့်သွင်းခြင်း

အကြံပြုချက်- နည်းပညာ၊ ဆေးပညာ စသည်ဖြင့် Domain ရွေးချယ်နိုင်ရုံသာမက User ကိုယ်တိုင် မကြာခဏ သုံးလေ့ရှိသော စကားလုံးများ (ဥပမာ - "Server" ကို "ဆာဗာ" ဟုသာပြန်ရန်၊ "ကွန်ပျူတာ" အစား "စက်" ဟုမပြန်ရန်) ကို သတ်မှတ်ပေးနိုင်သည့် Custom Dictionary/Glossary Feature ကို UI တွင် ထည့်သွင်းပေးပါ။ Gemini Prompt တွင် ထို Glossary ကို တွဲထည့်လိုက်ခြင်းဖြင့် ပိုမို တိကျသော ဘာသာပြန်ကို ရရှိပါမည်။

၂။ Human-in-the-Loop (မထုတ်ယူမီ ကြိုတင်ပြင်ဆင်ခြင်း)

အကြံပြုချက်- PDF ကို တန်းပြီး Export မထုတ်ခင်၊ ဘာသာပြန်ထားသော စာပိုဒ်များကို React UI ပေါ်တွင် စာရင်း (List/Table) အနေဖြင့် အရင်ပြသပေးပါ။ User မှ AI ဘာသာပြန်ထားသည်ကို သဘောမကျပါက ကိုယ်တိုင် ဝင်ရောက် Edit (ပြင်ဆင်) နိုင်သော စနစ် ပါဝင်သင့်ပါသည်။ ပြင်ဆင်ပြီးမှသာ "Generate PDF" ခလုတ်ကို နှိပ်စေခြင်းသည် အလွန် Professional ဆန်သော Feature ဖြစ်လာပါမည်။

၃။ Context-Aware Translation

အကြံပြုချက်- PDF စာမျက်နှာ တစ်ခုနှင့်တစ်ခု အကြား စာကြောင်းများ ပြတ်တောက်သွားတတ်ပါသည်။ နောက်စာမျက်နှာကို ဘာသာပြန်သည့်အခါ ယခင်စာမျက်နှာမှ နောက်ဆုံးစာပိုဒ်အချို့ကို Gemini ထံသို့ Context အဖြစ် ပူးတွဲပို့ဆောင်ပေးခြင်း ဖြင့် ဘာသာပြန် အချိတ်အဆက် (Flow) ပိုမို ချောမွေ့စေပါမည်။

💡 Phase 3: User Experience (UX) & UI Design (အသုံးပြုသူ အတွေ့အကြုံ)
၁။ Side-by-Side Live Preview

လက်ရှိအခြေအနေ- app.py (Gradio) တွင် မူရင်းနှင့် ဘာသာပြန်ထားသော ပုံများကို ယှဉ်ပြသည့် (Previews) စနစ် ပါဝင်သော်လည်း၊ React UI ဖက်တွင် ပိုမိုကောင်းမွန်အောင် ပြုလုပ်နိုင်ပါသည်။

အကြံပြုချက်- PDF.js ကို အသုံးပြု၍ React မျက်နှာပြင်တွင် ဘယ်ဘက်၌ မူရင်း PDF၊ ညာဘက်၌ ဘာသာပြန်ပြီးသား PDF ကို Real-time ယှဉ်ကြည့်နိုင်သော View တည်ဆောက်ပါ။ Scroll လုပ်ပါက နှစ်ဖက်စလုံး အတူတူ ရွေ့လျားသော (Sync Scrolling) စနစ် ပါဝင်ပါက အလွန်မိုက်ပါသည်။

၂။ Custom Font Upload စနစ်

လက်ရှိအခြေအနေ- App သည် Pyidaungsu.ttf တစ်ခုတည်းကိုသာ ပုံသေ အသုံးပြုထားပါသည်။

အကြံပြုချက်- User က ၎င်းတို့နှစ်သက်ရာ မြန်မာဖောင့် (ဥပမာ - Myanmar Text, Padauk) ကို Settings မှတစ်ဆင့် Upload တင်၍ ပြောင်းလဲအသုံးပြုနိုင်မည့် စနစ်ကို ထည့်သွင်းပါ။

💡 Phase 4: Storage, Security & Deployment (လုံခြုံရေးနှင့် သိမ်းဆည်းမှု)
၁။ Auto-Cleanup / Garbage Collection

လက်ရှိအခြေအနေ- ဖိုင်များကို Download လုပ်ပြီးပါက ဖျက်ပေးသည့် စနစ်ရေးထားသော်လည်း၊ User က Download မလုပ်ဘဲ ထွက်သွားပါက ဆာဗာတွင် ဖိုင်များ ပုံနေနိုင်ပါသည်။

အကြံပြုချက်- Cron Job (Node-cron) တစ်ခုကို ရေးသားပြီး uploads/ နှင့် outputs/ ဖိုင်တွဲများအတွင်းရှိ (ဥပမာ - ၂၄ နာရီထက် ကျော်လွန်နေသော) ဖိုင်ဟောင်းများကို အလိုအလျောက် ရှင်းလင်းပေးသည့် စနစ် (Storage Management) ကို မဖြစ်မနေ ထည့်သွင်းပါ။

၂။ API Key Security (Localhost အတွက်ပါ)

အကြံပြုချက်- React UI ပေါ်တွင် API Key ရိုက်ထည့်ပါက Browser ၏ localStorage တွင် အလုံခြုံဆုံးဖြစ်အောင် Encrypt လုပ်၍ သိမ်းဆည်းပေးပါ။ သို့မှသာ အကြိမ်ကြိမ် ရိုက်ထည့်နေစရာ မလိုဘဲ အသုံးပြုရ အဆင်ပြေစေပါမည်။
